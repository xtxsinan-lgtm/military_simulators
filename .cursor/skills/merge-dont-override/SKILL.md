# 发现其他改动时合并，不要覆盖

## 硬性规则

发现**其他改动**时，必须 **merge**，禁止 **override**。

以磁盘上、工作区里、远程上**当前最新内容**为底，只把本次要做的改动叠加上去。禁止用记忆中的旧版本整文件写回，禁止为了 diff 干净而丢掉不是你这次写的修改。

## 什么算其他改动

- `git status` / `git diff` 里已有、且不是本次任务刚写下的修改
- 准备编辑的文件，磁盘内容与上一轮读到的不一致
- 同一文件里用户或其他会话新增、改过的行、字段、测试、数据行
- 远程分支已领先，或 pull / push 时出现分叉、冲突

## 动手前

```
- [ ] 已看 git status 与目标文件的 git diff
- [ ] 已重新读取目标文件的当前内容（不以旧快照为准）
- [ ] 已标出哪些行是其他改动、哪些是本次要加的
```

## 怎么 merge

1. 用小范围补丁（在当前全文上改对应片段），不要整文件覆盖。
2. CSV / JSON / 源码：在**当前文件**上增删改对应条目。其他改动的行、列、字段保留。
3. 同一处两边都改了：保留双方意图，合成一份能通过测试的结果。说不清时先停下来问用户，不要选一边整段丢掉。
4. 与本次无关的其他文件：保持原样。提交时只加入本次相关文件，不要 `git restore` / `git checkout --` 清掉它们。
5. 远程分叉：在 **`main`** 上 `git pull origin main`（merge）后再 `git push origin main`。冲突时逐处合并双方。禁止 `git push --force`、`git reset --hard` 来盖掉其他提交。本仓库不走 feature 分支；见 `push-to-github`。
6. `docs/data.json`、`physics.js` 等**生成物**：先把源码 merge 好，再跑 `python3 scripts/build_all.py` 重建。不要手改生成物，也不要用旧生成物覆盖新生成物。

## 反例（禁止）

- 看到 CSV 已有未提交行，用旧数据整表写回
- 编辑对不上时，用整文件重写冲掉中途插入的改动
- 为了工作区干净，`git restore` / `git checkout --` / `git reset --hard` 丢掉其他改动
- 冲突时整文件采用「我们的」或「他们的」一侧
- 远程已有新提交仍 force push 覆盖
